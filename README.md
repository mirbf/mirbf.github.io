# 精选知识主题站点说明

这是一个用于发布到 GitHub Pages 的纯静态中文站点。它的定位不是“统一改造所有内容”，而是做一个很薄的总纲入口，把多个可独立运行的专题链接起来。

## 当前方案

- 技术路线：纯静态站
- 发布方式：GitHub Pages 直接发布仓库根目录 `/`
- 构建策略：无构建优先
- 总纲角色：只做专题入口，不接管专题内部结构
- 专题角色：各自独立运行，按原本的 HTML、CSS、JS、相对路径工作

## 明确不做的事

- 不使用 VitePress
- 不引入 `pnpm build`
- 不引入 Markdown 预编译流程
- 不引入 GitHub Actions 构建部署
- 不为了接入总纲而重写专题内部结构
- 不把不适宜公开的内容放进这个仓库

## 核心原则

- 这是“总纲薄层 + 专题独立”的结构。
- 总纲首页只负责列出专题卡片，并跳转到每个专题指定的入口文件。
- 专题内部的文件组织、页面跳转、脚本依赖、相对路径，原则上保持原样。
- 主题目录名优先使用用户指定的原始中文名或原始项目名，不强制改成 slug。
- 如果某个专题已有自己的入口页，就直接用它，不额外再包一层。
- 如果某个专题没有合适入口，再单独补一个最小入口页，但不要顺手重构整个专题。

## 公开边界

- GitHub Pages 会公开发布仓库中的静态文件。
- 因此，这个仓库里只能放确定可以公开的文件。
- “首页不展示”不等于“外部无法访问”。
- 如果文件已经进入公开仓库，只要 URL 被知道，理论上就可以直接访问。
- 所以不适宜公开的内容，不要放进这个仓库，连“先放进来以后再隐藏”也不行。

## 首页规则

- 首页文件是 `index.html`。
- 首页标题当前是“精选知识主题”。
- 首页卡片只展示两项内容：专题标题、100 字以内的真实内容简介。
- 不展示“进入专题”按钮文案。
- 点击专题卡片后，在新浏览器标签页打开专题入口。
- 首页是薄层导航，不承担专题简介页、专题索引页、专题结构页的职责。

## 已知实现细节

- `.nojekyll` 需要保留，避免 GitHub Pages 对以下划线等静态文件做 Jekyll 处理。
- `404.html` 已存在，可继续保留为 GitHub Pages 的兜底页面。
- `topics/OPC/content.js` 做过一处兼容性调整：
- 当它不是运行在父级导航容器中时，内部链接会直接跳转当前页面。
- 浮动上一页/下一页按钮只在父级导航模式下显示。
- 除这类“保证专题能独立跑起来”的兼容性修复外，不要主动改专题内部逻辑。
- 某些文件名里即使带有 `private`、`public` 一类字样，也不能只凭文件名判断是否应公开，必须按实际内容判断。

## 新增专题时的操作规则

- 先确认该专题的全部文件都适合公开。
- 确认专题是否已经能作为独立静态站运行。
- 明确这个专题的唯一入口文件，不一定非要叫 `index.html`。
- 把专题所需的 HTML、CSS、JS、图片、数据文件完整放进 `topics/专题名/` 下。
- 尽量保持原本的目录层级、文件名、相对路径不变。
- 不要为了“统一风格”去改专题内部 UI。
- 只在首页增加一张专题卡片，并链接到该专题的入口文件。
- 如果专题运行依赖绝对路径、父页面、跨目录资源或外部私有文件，先修通再接入总纲。

## 新增专题的标准步骤

1. 确认专题可公开。
2. 确认专题入口文件。
3. 把专题复制到 `topics/专题名/`。
4. 删除不必要的非公开文件、开发文件、仓库残留文件。
5. 在本地用静态 HTTP 服务验证入口页能正常打开。
6. 点击入口页内部导航，确认相对路径资源正常。
7. 在首页增加卡片链接。
8. 再次验证首页到专题入口的跳转。

## 不应带入公开仓库的内容

- `.git`
- 私有笔记
- 草稿数据
- 仅供本地使用的源材料
- 未经确认可公开的图片、附件、表格
- 密钥、账号、Cookie、接口凭证
- 名称看似普通但实际不应公开的文件

## GitHub Pages 限制

这个站点当前依赖 GitHub Pages，后续维护时必须记住这些边界：

- GitHub Pages 本质上是静态站托管，只适合 `HTML`、`CSS`、`JS`、图片、数据文件等静态资源。
- 它不提供服务端程序、数据库、登录后端、权限控制接口。
- 当前这个仓库里的文件一旦推送并发布，理论上都可能被直接访问，首页不展示不等于外部不可访问。
- 因此，这个仓库只能放确定可公开的内容。
- 用户主页站点仓库名必须匹配账号名，例如当前站点使用 `mirbf.github.io`。
- GitHub 官方建议 Pages 源仓库不超过 `1 GB`。
- 已发布站点大小也不应超过 `1 GB`。
- 部署时间超过 `10 分钟` 可能失败。
- Pages 带宽存在软限制，官方说明为每月 `100 GB`。
- 如果使用“从分支发布”的方式，官方说明构建存在软限制：每小时 `10` 次。
- 当前仓库正是从 `main` 分支的 `/ (root)` 发布。
- 如果未来频繁连续推送，可能遇到 Pages 构建排队或延迟。
- GitHub 还可能对访问做速率限制，流量异常时可能出现 `429` 等限制响应。
- GitHub Pages 不适合承载密码、支付、私密资料、受限分发内容。
- 如果未来要做权限、搜索后端、数据库或复杂交互系统，应改用其他托管方案，不要硬塞进当前纯静态架构。


说明：
